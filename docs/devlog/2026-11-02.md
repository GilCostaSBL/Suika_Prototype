# Devlog 2026-11-02

## Goal for this session
Set up the project: repo, tooling, docs vault.

## What we did
- Chose Suika, GDScript, GitHub, trunk-based workflow, and an Obsidian vault in `docs/`.
- Installed the GitHub CLI (winget).
- `git init` with Godot and Obsidian-aware `.gitignore`, plus `.gitattributes` (LF).
- Created a minimal `project.godot` (portrait 720×1280, GL Compatibility) and verified it imports headless.
- Scaffolded the vault: GDD with the twist backlog, decision 0001, templates.

### M1 — Core clone
- `fruit_data.gd` (11 tiers, triangular scoring), `fruit.gd` (RigidBody2D, drawn circles; no art yet), `game.gd` (jar built in code, dropper follows the mouse, release to drop, 0.5 s cooldown, next preview, danger line with a 2 s grace, R or click to restart).
- Merges are detected by polling `get_colliding_bodies()` every physics tick rather than `body_entered`, so twins that are already resting against each other still merge.
- Physics at 120 ticks/s for steadier stacking.
- Headless smoke test `tests/smoke_test.gd`: cherry merge, watermelon vanish, danger-line game over. Passes.

### Playtest feedback round 1
- User liked the feel and proportions; no tuning needed.
- Widened the viewport to 1200×1280 (window 1020×1088 to fit all monitors) with the jar unchanged on the left and an Abilities panel on the right.
- Added keyboard controls through input actions. The mouse kept leaving the window and clicking other apps.
- Smoke test extended with keyboard checks (8/8 pass).
- Claude verified the layout by rendering frames with `--write-movie` and reading the PNG, a workaround for not being able to see the game window.

### M2 — Abilities and coins
- User decisions: 1 coin per 50 points (tunable), abilities per run, costs 5 / 10 / 25.
- Tuning moved into `config/balance.tres`, editable in the inspector.
- Fruit Slot (stash, then free release), Fruit Swap (reroll next), Shake Up (cover, zoom, 4 × 180° flips). Keys 1/2/3 plus panel buttons.
- Shake Up rotates the view and gravity instead of the physics jar ([decision 0002](../decisions/0002-shake-up-rotates-the-view.md)).
- **Bug caught by rendering, not by tests:** the first version passed every test but fruit never left the old floor. Fruit needs ~1.35 s to cross the jar and the pause was 0.3 s. Fixed with a gravity boost and a longer pause, and added a test asserting fruit actually falls after a flip.
- Smoke test: 28 checks, all pass.

### Shake Up revision
- User confirmed: pay per use, swap rerolls next, the 0.6 zoom. Changed the turn to 4 × 90° (360° total), waiting for fruit to settle after each.
- Measured with a probe script: fruit kept rolling at 200–300 px/s (circles have no rolling resistance), so every settle hit the cap. Fixed with shake-only damping and an average-speed settle rule. Settles now take ~1–1.5 s; a full shake ~8–10 s.
- Smoke test: 29 checks (adds "fruit settles on the new floor after a 90° turn" and "4 turns made").
